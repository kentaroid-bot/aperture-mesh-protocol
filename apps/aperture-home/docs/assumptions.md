# Aperture Home MVP — 前提と用語

## 実装前提

- 同意した1家庭が自分たちの端末で試す、ローカルファーストの実験版である。
- 家庭は2人以上の有効な Member Node で構成し、合意数は固定人数ではなく影響ノード集合から計算する。
- この端末で選択した利用者だけが通常UIから本人の Monku と Safety データへアクセスする。
- IndexedDBを正本とし、クラウド同期、遠隔バックアップ、テレメトリー、実際の外部送信は行わない。
- AIは初期状態で無効。MVPではローカルテンプレート変換のみ利用でき、remote adapterは常に無効である。
- Protocol Constitution v1.0は通常設定、投票、Revision、AI提案から変更できない。
- ContractとRevisionは上書きせず、Versionまたは新規レコードを追加する。
- SOSは判決・通報・制裁ではなく、本人専用の安全確認を開始する Protected Interrupt である。

## 用語集

| 用語 | MVPでの意味 |
| --- | --- |
| Node | 家庭内の独立したメンバー。内面は評価しない。 |
| Contract | 入力、出力、期限、境界、停止条件を明示した接続条件。 |
| Monku | 作成者だけが読める端末内の非公開メモ。 |
| Revision | Contractを直接上書きしない、構造化された変更差分。 |
| Affected Nodes | Revisionの影響を受け、合意計算の分母となる有効ノード集合。 |
| Cooldown | 判定や自動制裁を伴わない、期限付きの限定接続。 |
| Protected Interrupt | SOSを有罪判定に変えず、安全な選択肢を表示する割り込み。 |
| Capability Lease | scope、purpose、TTLを必須とする期限付き権限。 |
| Safe Channel | 本人だけが閲覧できる、アプリ外の連絡先メモ。 |
| Audit Chain | 秘密本文を含めない追記専用ハッシュチェーン。 |

## 非目標

実装指示書の「実験版では実装しない」全項目を非目標とする。特に、常時録音、感情・人格・責任判定、自動通報、スマートロック等の物理制御、位置追跡、秘密管理者、親による全閲覧、報酬、暗黙同期、不可逆制裁は実装しない。

UI仕様にある「不満度」「音声エントロピー」「物理アクセス制限」「家庭内リソースを報酬化する表示」は安全境界と衝突するため採用しない。

## 未決事項と制約

- 単一ブラウザプロファイル内のローカルアカウントであり、OS利用者を暗号学的に識別するものではない。
- WebAuthnは端末・ブラウザ差が大きいため、MVPはローカルPINによるアプリロックを提供する。共有端末での強い隔離にはOSアカウント分離が必要。
- ブラウザの時計は信頼できないため、時刻巻き戻しを検知したLeaseは再確認待ちにするが、信頼できる時刻証明にはならない。
- 暗号化エクスポートのパスフレーズを失うと復元できない。
