# 脅威モデル

## 資産と境界

最重要資産は private Monku、Safety Incident、Safe Channel、暗号鍵である。通常の契約・Revision・秘密本文を含まない監査イベントとは分離する。データはこのブラウザのIndexedDBに留まり、ネットワーク送信は実装しない。

## 想定する脅威と軽減策

| 脅威 | MVPの軽減策 | 残る制約 |
| --- | --- | --- |
| 同じ端末を別メンバーが開く | 利用者切替時にロック。PIN由来鍵で本人データを暗号化 | ロック解除済み画面の覗き見やOS管理者は防げない |
| 親・管理者が他者のMonku/SOSを読む | ownerIdでrepositoryを分離し、復号鍵はメモリ内のみ。秘密管理者UIなし | 同一OSアカウントの開発者ツールや端末侵害には完全耐性なし |
| 多数派が少数者の権利を縮小 | Constitution純粋関数を全write前に実行し、本人同意を別条件にする | 現実世界の強制はアプリだけでは防げない |
| 履歴・通知・プレビューからSOSが露見 | 一般的な画面タイトル、通知本文なし、Safety離脱時に状態を破棄 | ブラウザ履歴にアプリ利用自体が残る可能性 |
| AIへ不要な情報を送る | remote AIは無効。将来用adapterも明示opt-inとpreviewを要求 | MVPではremote AIを利用できない |
| 端末紛失後もLeaseが残る | TTL、自動失効、取消、時刻巻き戻し時の再確認 | オフライン端末の信頼できる時刻は保証できない |
| 監査ログが証拠本文の集積所になる | action/resource/idのみをハッシュ化し、秘密本文を拒否 | 操作の存在と時刻は残る |
| exportが平文で放置される | AES-GCM暗号化JSONを既定かつ唯一の形式にする | 弱いパスフレーズや復号後の扱いは利用者責任 |
| IndexedDBの改ざん | 監査ログのSHA-256チェーン検証 | 端末を完全に支配した攻撃者はチェーンごと置換可能 |

## 安全上の注意

このアプリは緊急対応、医療、法律相談、児童保護の代替ではない。現実の危険がある場合はアプリ内手順より安全確保を優先する。SOSは外部へ自動送信されず、誰かを有罪と判定しない。
